# Promise/Pending carryover fix — working notes (28/7)

User request: Promise to Pay / Pending Follow-up must NOT reset at month change;
they stay active until their target date passes. Promise date is now MANDATORY.

## Changes done in server/routers/ar.ts
- `isConfirmationStale(status, followUpDate, now)`: Not Contacted → stale; Broken → never stale;
  Confirmed/Pending → stale only when followUpDate < now (no date = stale).
- `effectiveConfirmation(row)` now reads row.followUpDate (not updatedAt).
- `getConfirmationStatus` query uses new signature.
- `logCall`: followUpDate column now stores promisedDate for Confirmed; requires promisedDate
  for Confirmed (amount>0) and followUpDate for Pending Follow-up (BAD_REQUEST otherwise).
- `updateConfirmationStatus`: stores followUpDate for both Pending Follow-up and Confirmed.
- LogCallDialog.tsx: client-side validation requires follow-up date for Pending Follow-up
  (promised date already required for Confirmed).
