# AR Pro — Application Audit (Aug 2026)

## 1. Correctness

- `tsc --noEmit`: clean.
- Vitest: 96 files / 643 tests green after fixes. Two suites (`contactTracking`,
  `contactCollapse`) still asserted a UI shape that had since changed; updated.
- No runtime errors in `.manus-logs/devserver.log` or `browserConsole.log`.

## 2. Test residue in the live database (fixed)

Several suites wrote against **real** customers and never cleaned up. Removed:

| Rows | Table | Origin |
|---|---|---|
| 69 | activity_log on "!!OSW ESCHBACH GMBH" | logCallNoTasks, logCall* suites |
| 12 | promises_to_pay | same |
| 293 | activity_log / notes / mentions (orphaned groups) | fixture suites without cleanup |
| 244 | invoices | confirmationTaskLink fixtures |
| ~250 | customers + payment_contacts | contactsImport / logCallTimelineDetail |

Hardening applied:

- `server/testFixtures.ts` cleanup now also deletes payment contacts, activity
  log, notes, mentions and watch status.
- `server/testCleanup.ts` snapshot cleanup extended to `note_mentions` and
  `payment_contacts`.
- `logCallNoTasks.test.ts` uses an isolated fixture group instead of the first
  real customer.
- `confirmationTaskLink.test.ts` deletes its fixture invoices before customers.
- New `server/dataIntegrity.test.ts` fails the suite if any test leaves residue.

Post-cleanup live counts: 3,409 customers / 5,424 invoices / 7,491 contacts,
zero orphan rows.

## 4. Performance

### Database indexes added (migration `0045`)

`customers.customerGroup`, `activity_log(group, createdAt)`,
`payment_contacts.customerId`, `promises_to_pay.customerId`,
`group_notes.group`.

### Response payloads trimmed

| Endpoint | Before | After |
|---|---|---|
| `customers.list` | 4,037 KB | 2,573 KB |
| `addressBook.contacts` | 4,300 KB | 2,962 KB |
| pickers (5 dialogs) | 4,037 KB each | 420 KB (`customers.options`) |
| Log Call dialog members | 4,037 KB | one group only (`customers.groupMembers`) |

Causes: hidden search haystacks repeated text that was already in visible
columns; `companyNames`/`groupNames` arrays duplicated the joined strings;
`ratingFactors` shipped a full sentence per factor per company (2 MB) for a
tooltip.

### Frontend bundle

Recharts moved out of the initial bundle into a lazy `CashFlowChart` chunk
(410 KB, loaded only when the dashboard chart appears); orphan pages and unused
deps dropped. Initial chunk is now 808 KB (was ~1.2 MB), total assets 2.5 MB.

### Table rendering

The Desk **Companies** tab rendered all 3,409 rows into the DOM. It now pages
200 at a time with Show more / Show all, matching the Invoices and Address Book
behaviour. Filters, sorting and the TOTAL row still work on the full set.

### Test-suite stability

`vitest.config.ts` timeout raised from the 5s default to 30s: nearly every suite
hits the remote TiDB, and back-to-back runs were flaking on latency, not on
logic.

## 5. Open items / recommendations

- `server/lib/taskEngine.ts` exists but nothing runs it automatically. Either
  wire it to a Heartbeat schedule or remove it.
- Email sending is Outlook-based (`mailto`/draft), not server-side SMTP; the
  status wording was clarified in `server/routers/ar.ts`.
- The Desk **Groups** tab renders all 363 rows. That is acceptable today, but if
  the group count grows past ~1,000 it should page like the Companies tab.
- Final state: 97 test files / 656 tests green, typecheck clean, no orphan rows
  in the database.
